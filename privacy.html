Privacy Policy

Last Updated: October 2026 · Data Controller: sidoua26

This privacy policy explains our commitment to transparency regarding this portfolio website (the "Site") and provides a factual overview of how our browser extensions process user data.

1. The Portfolio Website

This portfolio is a 100% static client-side website designed to showcase browser extensions. Our server-side footprint is zero.

  • No Cookies or Tracking: The Site does not set any cookies, advertising beacons, or tracking identifiers.
  • No Analytics: There are no third-party analytics scripts (such as Google Analytics or tracking pixels) running on the Site.
  • Local Storage (Theme Preference): The Site uses your browser's localStorage solely to save your choice of Light or Dark mode (theme). This data is stored strictly on your device and is never transmitted to any server.
  • External Fonts: The typography is provided via Google Fonts (fonts.googleapis.com). When you load the Site, your browser requests font files directly from Google's content delivery network according to Google's standard privacy policies.
  • External Links: Clicking store links redirects you to third-party marketplaces (Microsoft Edge Add-ons and Chrome Web Store) or GitHub, which have their own respective privacy policies.

2. Browser Extensions Data Handling

Every extension listed in this portfolio is designed to respect your privacy with minimal permissions and clear data boundaries. Below is an accurate breakdown by product:

Word to LaTeX (Offline)

Runs fully offline, nothing leaves your device. All document parsing (Pandoc WebAssembly) and optical character recognition (Tesseract.js) execute entirely inside your local browser sandbox without network communication. Requests permissions: [] in its Manifest V3 definition.

Table Extractor

Your table data stays in your browser; nothing is sent to any server. Scans and processes HTML tables and virtualized data grids locally in your active tab upon explicit user interaction (using activeTab and scripting).

BulkGrab

Files download directly from the source site to your device and are bundled locally; no upload to my servers. Downloads are managed directly by your browser's native download manager without proxying files through any remote server.

SEO Inspector

Analyzes the page in your browser; no data sent to any server. Evaluates page DOM structure, meta tags, schema markup, and performance timing in-memory on the active tab without logging or transmitting browsing history.

AuditPilot

Unlike Word to LaTeX, AuditPilot uses a client-server architecture with external AI integration to provide conversion rate optimization and technical audits. Its data handling operates as follows:

  • User-Initiated Audits: Audits run strictly on-demand when you click the extension on an active tab. It never monitors, scans, or records browsing history in the background.
  • Page Data Transmitted to Backend: When an audit is triggered, the extension sends page structure and visible text to our backend API (https://auditpilot-dc8n.onrender.com), including:
    • Page metadata: URL, hostname/domain, page title, language, meta description, canonical link, and robots directives.
    • Structural elements: Viewport dimensions, up to 50 heading elements (H1–H6), and up to 15 call-to-action buttons/links.
    • Page indicators: Up to 5 form summaries (field count and non-hidden input types), contact details found on the audited page (up to 10 phone numbers and email addresses extracted from tel:, mailto:, and contact links), scheduling/booking links (e.g. Calendly, HubSpot), pricing links, image counts, link counts, and Schema.org / OpenGraph structured data types.
    • Visible body text: Up to 6,000 characters of visible rendered text from the active page (from innerText or DOM TreeWalker, excluding scripts, styles, and hidden elements).
    • Viewport Screenshot (Optional): If enabled, a base64-encoded screenshot of the visible viewport (validated under 3.5MB).
  • External AI Transmission (Google Gemini):
    • Our backend wraps the sanitized page data and visible text excerpt into an untrusted passive data prompt and transmits it to the Google Gemini API (using the official Google GenAI SDK, calling gemini-3.8-flash / gemini-3.6-flash) to calculate category scores, identify conversion roadblocks, and generate copy suggestions.
    • If the external AI API is unreachable or times out, the backend falls back to an internal deterministic heuristic scoring engine.
    • Screenshots are never transmitted to Google Gemini; they are processed solely on our backend to embed into generated PDF audit deliverables.
  • Data Stored on Server:
    • User account identifier, API key, email (if provided), and audit credit balance.
    • Completed audit records: audited URL, domain, page title, generated scores, executive summary, findings, copy rewrites, a metadata snapshot (primary H1, title, meta description, top headings/CTAs, contact links), and the optional screenshot.
    • White-label agency branding settings, if configured (auditor name, agency name, contact info, logo URL).
    • Public share tokens: Random 16-byte cryptographic tokens enabling read-only web report sharing.
  • Hosting Infrastructure & Database Providers:
    • Backend Hosting: Hosted on Render (onrender.com), providing SSL/TLS termination and web service execution.
    • Database Storage: Stored in a managed PostgreSQL database connected via Prisma ORM (specified by DATABASE_URL environment configuration).
  • Data Retention & Security:
    • Signed PDF report download tokens expire automatically after 15 minutes (15-minute TTL).
    • Audit records are persisted in PostgreSQL to allow auditors to review historical reports and export PDFs. (Note: There is currently no automated expiration cron job for stored database audit records).
    • Target URLs are validated against Server-Side Request Forgery (SSRF), blocking requests to loopback addresses, private subnets (RFC 1918), and cloud metadata endpoints.
