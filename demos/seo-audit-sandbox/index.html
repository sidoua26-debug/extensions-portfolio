1. Correct versus Missing H1 Heading

Healthy (Baseline)

Defect Mechanics: The primary document heading is rendered as a styled <div> or paragraph with visual CSS styling rather than a semantic <h1> element. While humans see large bold text, search engine indexers and assistive screen readers fail to recognize the document's primary topic.

Toggle to replace the page's actual top <h1> with a styled <div>.
Healthy Semantic Markup
<!-- Valid Top-Level Document Heading -->
<h1>Technical SEO Debugging Sandbox</h1>
Defective Presentation Markup
<!-- Non-semantic visual text (H1 missing from DOM) -->
<div class="text-4xl font-extrabold">Technical SEO Debugging Sandbox</div>
How to inspect with SEO Inspector: Open the extension popup in Edge. In the Overview tab, observe the "H1 Heading" indicator drop from 1 to 0 with a yellow warning tag.

2. Skipped Heading Levels (H2 Jumping Directly to H5)

Healthy (Baseline)

Defect Mechanics: An <h5> heading is nested directly under an <h2> section, omitting intermediate <h3> and <h4> levels. While HTML5 parsers tolerate this and search engines will still index the content, it creates ambiguous section outlines and breaks accessibility navigation for users who browse via screen reader heading shortcuts.

Toggle to replace the child <h3> below with an out-of-sequence <h5> in the live DOM.
Live Heading Hierarchy Container:
<h2> Parent Section Context

<h3> Sequential Section Heading

Valid logical progression: parent <h2> followed properly by child <h3>.

Educational note: Google does not penalize rankings solely for skipped heading levels, but W3C WCAG guidelines require logical heading progression for screen reader accessibility.

3. Correct versus Mismatched Canonical URL

Healthy (Baseline)

Defect Mechanics: The <link rel="canonical"> element specifies an unencrypted http:// scheme or omits the mandatory trailing slash. In production, this causes indexers to split link equity, flag duplicate content issues, or select an unwanted version as the canonical result.

Toggle to mutate <link rel="canonical"> in <head> to an insecure, non-slash URL.
Self-Referencing HTTPS Canonical
<!-- Exact match to current document URL -->
<link rel="canonical" href="https://extensionguy.me/demos/seo-audit-sandbox/">
Mismatched Protocol / Path
<!-- Missing trailing slash & insecure HTTP protocol -->
<link rel="canonical" href="http://extensionguy.me/demos/seo-audit-sandbox">
How to inspect with SEO Inspector: View the "Canonical URL" panel in the extension. When the defect is active, it flags a canonical mismatch between current browser URL and declared href.

4. Missing & Incomplete Open Graph Metadata

Healthy (Baseline)

Defect Mechanics: Sharing cards on platforms like LinkedIn, Slack, or X require valid og:image, og:title, and og:description tags. Omitting social image or description metadata causes shared previews to fall back to blank grey cards or pull arbitrary body graphics.

Toggle to remove og:image and og:description from the live document <head>.
Complete Open Graph Bundle
<meta property="og:title" content="...">
<meta property="og:description" content="...">
<meta property="og:image" content="https://.../card-1200x630.png">
Missing Crucial Preview Assets
<!-- og:image and og:description omitted from <head> -->
<meta property="og:title" content="...">
How to inspect with SEO Inspector: The "Social Metadata" tab highlights missing card requirements in red, detailing absent image dimensions and title tags.

5. Valid versus Malformed JSON-LD Syntax

Healthy (Baseline)

Defect Mechanics: RFC 8259 JSON syntax strictly forbids unquoted keys and trailing commas after the last key-value pair. When developers manually concatenate JSON strings or fail to lint template output, parsers abort with syntax exceptions, causing search engines to ignore all rich structured snippets.

Toggle to inject an invalid JSON-LD script block containing trailing commas and unquoted keys.
Valid RFC 8259 JSON-LD
{
  "@context": "https://schema.org",
  "@type": "WebApplication",
  "name": "Valid App"
}
Malformed JSON Syntax
{
  "@context": "https://schema.org",
  unquoted_key: true,
  "name": "Broken App",  <!-- Trailing Comma -->
}
Educational note: JSON syntax validation (whether JSON.parse() succeeds) is distinct from Schema.org semantic validation (whether the properties adhere to schema definitions). Both must pass for rich search snippets to render.

6. Multiple H1 Headings in a Single Document

Healthy (Baseline)

Defect Mechanics: The document declares more than one <h1> element. While the HTML5 outline algorithm historically permitted multiple H1s inside separate <section> tags, major browsers did not implement the outline algorithm natively, and assistive screen reader users expect one primary H1 declaring the document's core subject.

7. Client-Side DOM Mutations (Hydration Differences)

Healthy (Baseline)

Defect Mechanics: Modern single-page applications (SPAs) and hydrated frameworks (React, Next.js, Vue) frequently modify or inject headings, meta descriptions, or structured data via client-side JavaScript after the initial HTTP page load. Right-clicking and selecting "View Source" shows only initial server HTML, whereas live in-browser DOM inspection captures the true user-facing and Googlebot-rendered state.
