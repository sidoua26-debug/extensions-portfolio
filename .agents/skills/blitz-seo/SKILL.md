# Blitz SEO: Focused 30-day sprint for ExtensionGuy

Concentrate optimization effort on a single high-priority ExtensionGuy page (e.g. `/word-to-latex-converter/`, `/pdf-tools/`, or a key technical guide like `/guides/redact-pdf-without-uploading/`).

> **Note on Upstream Claims:** Upstream case studies (e.g. moving from #11 to #3, traffic up 720%) are illustrative examples requiring verification. SEO outcomes depend on search engine evaluation, competitive landscape, and domain factors; never promise guaranteed positions or traffic.

## Initial assessment for ExtensionGuy

1. **Target candidate**: High-intent, utility-driven pages tied to core tools or extensions (e.g. offline Word-to-LaTeX converter, client-side PDF redaction, browser tab manager).
2. **Current visibility**: Pages indexed with established queries (from Google Search Console exports) that need structural refinement or topical reinforcement.
3. **Value alignment**: Prioritize tools and extensions that demonstrate ExtensionGuy's technical depth and on-device privacy architecture.
4. **Source of truth**: Identify whether the page is generated by `build_redesign.py` or authored statically in `guides/` before proposing changes.

## The sprint workflow

### Step 1: Pick one target page and core search intent
- Select one primary URL and its core verified user queries (from Google Search Console data).
- Ensure alignment with what the tool actually performs (e.g. client-side privacy, specific file conversion limits).

### Step 2: On-page technical and content optimization
- Descriptive, keyword-aligned title tag and H1.
- Clear technical explanation in the opening 40 words highlighting the on-device mechanism.
- Verifiable limits and specifications (e.g. file size caps, supported formats).
- Structured data (TechArticle, SoftwareApplication, or WebApplication) aligned with Google Rich Results guidelines.
- Responsive layout and fast TTFB on Cloudflare Pages.

### Step 3: Progressive 30-day plan
- **Internal Linking**: Route contextual links from related guides and demo pages to the target page using natural, descriptive anchors.
- **Outreach & Directory Preparation**: Draft curated prospect lists and contextual pitches for relevant developer roundups or open-source tool collections.
  - *Constraint*: Produce draft lists and copy only; do not send emails or submit listings without explicit user request.
  - *No Paid Links*: Never recommend or purchase paid links or sponsored placements.
- **Search Console Monitoring**: Review Search Console query impressions and position trends; adjust metadata based on verified queries.
- **Product Launch State**: ExtensionGuy tools and extensions are already launched on Product Hunt; do not repeat initial launch workflows.

## Output

When invoked, generate a structured, executable sprint plan:
1. Target page and search queries with rationale.
2. Concrete on-page refinement checklist (specifying maintained source files to edit).
3. Contextual internal link candidate list from existing guides and demos.
4. Curated outreach and directory draft opportunities (for user review).
5. Review cadence and log format.

## Verification & Execution Rules
- One focused task at a time with proportionate verification.
- Always edit maintained sources and run `python3 build_redesign.py` if changing generated pages.
- Verify changes with relevant tests before proposing deployment.
